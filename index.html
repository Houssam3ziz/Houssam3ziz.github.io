About

Products that survive real conditions — not demos.

I work on the App Development team at Children’s Cancer Hospital Egypt 57357, where the apps I ship are used by patients’ families to read lab results, track growth charts and manage appointments. Reliability isn’t a feature there; it’s the baseline.

Outside the hospital I build ERP systems end-to-end for retail businesses — gold shops and clothing stores — where the internet drops mid-sale and the cashier still has to print a receipt. That shaped how I design: local database as source of truth, a sync outbox, repositories that hide storage, and Cubits that never touch I/O directly.

I own the whole slice when needed: Flutter on phone, tablet and desktop; Laravel APIs with multi-tenant permissions and idempotent sync; Filament dashboards; store releases and over-the-air patches. I care about maintainability over cleverness — feature-first folders, typed failures, tests around the money-moving code, and docs the next engineer can actually use.

Engineering philosophy

Rules I actually follow in the codebases above.

Local first, then sync

The device database is the source of truth. Every write lands in Isar or Drift inside one transaction, then an outbox pushes it to the API when connectivity returns.

ZA Gold Flow · Fashion ERP · I.C.I

Cubits never touch I/O

Repositories own Dio, Isar and Firebase. Cubits orchestrate state from watch streams and typed results, so screens stay testable and swappable.

Every feature-first codebase

Failures are values

API calls return Either<Failure, T> through a single safeApiCall, so error handling is uniform and never an afterthought.

57357 apps · Out Services

Test the money paths

Pricing, stock deltas, instalments, receipts and sync ordering are covered by unit tests before UI polish — 70+ test files across the ERP products.

Fashion ERP · ZA Gold Flow

Security is a feature

Biometric locks, secure-mode screens, device-bound tokens in secure storage, restricted API keys and server-side permission resolution.

Ana 57357 · AttendSmart

Architecture blueprints, per-feature docs and loading-practice guidelines — so the next engineer (or future me) doesn’t reverse-engineer the codebase.
